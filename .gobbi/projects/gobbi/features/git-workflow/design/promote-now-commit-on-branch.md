# Commit-on-branch for Preparation promote-now (D-3)

## Context

`preparation/SKILL.md` has a narrow exception that allows a skill to be generated and copied into the worktree during Preparation (the "promote-now" path). Before this design, that path copied the generated skill body but did not commit it, leaving the artifact outside worktree-first history until some later commit happened to pick it up. The open question was whether the promote-now path should close itself by committing the generated artifact to the worktree branch, and how to recover if that commit fails after the copy.

## Decision

Extend `preparation/SKILL.md` narrow-exception promote-now path to run a worktree-branch commit as its closing step:

```
git -C "$worktreePath" add <promoted-files>
git -C "$worktreePath" commit \
  -m "chore(skills): promote {slug} generated by preparation iter{n}" \
  -m "AI-Provenance-Record: gobbi://session/{session-id}/task/preparation-promote-now-iter{n}"
```

**Partial-failure rollback**: if `git commit` fails post-copy, manager MUST `git -C "$worktreePath" rm` the copied file and surface to user via AskUserQuestion before re-attempt.

## Rationale

The Preparation promote-now path (narrow exception allowing skill generation during Preparation) was already a sole-writer deviation; commit-on-branch is the structural completion that ties the generated artifact into worktree-first history. The `-C "$worktreePath"` flag is explicit about which tree receives the commit. The canonical `AI-Provenance-Record` trailer form is `gobbi://session/{session-id}/task/{task-id}` per `git/conventions.md`. The rollback mechanism (git rm after failed commit) addresses the partial-promotion failure mode where a copied file must be removed if the commit cannot complete.

## Alternatives considered

- **`feat(skills):` subject** — rejected: the skill is generated by workflow automation, not authored as a user-facing product feature, so `chore(skills):` is the honest type.
- **An alternative `AI-Provenance-Record` trailer form** — rejected: a new trailer shape would require a separate Scope Contract item; the current `gobbi://session/{session-id}/task/{task-id}` slot is expressive enough to identify the promote-now operation.

## Consequences

The promote-now path now ends in a worktree-branch commit, tying the generated skill into worktree-first history. Any executor implementing this path must include the partial-failure rollback (`git rm` the copied file on commit failure, then AskUserQuestion) — see `decisions/2026-05-24-rollback-semantics-drift-from-ideation.md` for why `git rm` (not `git checkout`) is the only correct recovery. Verification: a future-session smoke test confirms `git log --oneline` for the next `generate-now` shows a subject matching `^chore\(skills\): promote .*` with a body containing `AI-Provenance-Record: gobbi://session/[a-f0-9-]+/task/preparation-promote-now-iter[0-9]+`.
