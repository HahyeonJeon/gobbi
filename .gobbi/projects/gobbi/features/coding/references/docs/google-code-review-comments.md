# How to write code review comments (Google eng-practices)

## Insight
Good review comments are courteous, specific to the code, and explain the reasoning (the why) rather than only naming a preferred replacement. The reviewer distinguishes required changes from optional suggestions, and gives feedback on the code, not the author.

## Reason
Anchors the comprehensive taxonomy's first-class Review-Communication point (#13) and the procedure's Write-Findings phase: a correct finding written poorly causes churn, so the doc must teach comment discipline alongside what to check. Complements Conventional Comments (the label format) with the substance (be useful, specific, explain why, separate blocker from suggestion).

## Source
- https://google.github.io/eng-practices/review/reviewer/comments.html
- Google Engineering Practices — Code Review Developer Guide

## Excerpt
Be courteous; explain your reasoning; balance giving explicit directions with pointing out problems and letting the developer decide; distinguish required changes from suggestions ("Nit:" / "Optional:").
