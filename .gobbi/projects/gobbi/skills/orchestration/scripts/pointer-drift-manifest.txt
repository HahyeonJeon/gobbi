# pointer-drift-manifest.txt
# Reviewed baseline data file for check-workflow-pointer-drift.sh. This file — NOT
# an in-script expected=(...) array — is the source of truth for the workflow doc
# set, each doc's expected doc-kind, and each doc's role flags. Per
# mistakes/verification/hardcoded-baseline-guard-*, a guard that hardcodes its
# baseline is a hidden third copy of the spec; keeping it here makes the baseline
# a reviewed member of every compaction PR's file set. The guard hardcodes NO doc
# name — every doc-specific role (compacted / no-commit owner / perspective-table
# owner) is a flag below.
#
# Format (one row per doc):  doc|<filename>|<doc-kind>|<flags>
#   <doc-kind> is one of: loop-orchestration, gate-orchestration,
#                         reference-orchestration
#   <flags>    "-" (none) OR a comma-separated list of:
#       compacted             the doc HAS been compacted, so the structural
#                             compaction-invariant checks apply to it:
#                               #2 all-5 typed owner pointers (loop docs only)
#                               #3/#7 no fenced session-tree redraw (loop OR gate)
#                             A doc that is neither `compacted` nor `tree-free` is
#                             pre-migration: it legitimately still carries its ASCII
#                             tree / long procedure, so these checks do NOT run on it.
#                             Add `compacted` only in the same PR that compacts the doc.
#       tree-free             the doc has had its redrawn session/output tree removed
#                             (replaced by the Output-Pointers prose form), so #3/#7
#                             (no fenced session-tree redraw) DOES apply to it — a
#                             re-added tree FAILS. Unlike `compacted`, a `tree-free`
#                             doc is NOT required to carry all five typed owner
#                             pointers (#2 stays compacted-only). Add `tree-free` in
#                             the same PR that removes the doc's tree.
#       nocommit-owner        the doc OWNS the no-commit git-mechanics rule, so it is
#                             EXEMPT from the broad #4 no-commit-restatement check
#                             (every OTHER doc must point at the owner, never restate).
#       no-perspective-table  the doc must NEVER carry a horizontal seven-perspective
#                             table (#6) — it points at the perspective list instead.
#
# Fail-closed: a malformed row, a bad kind, an unknown flag, a duplicate doc, a
# manifest doc missing on disk, OR an on-disk workflow/*.md not listed here all
# exit 2. Partial migration: ideation.md is `compacted`; planning / execution /
# wrap-up are `tree-free` (redrawn tree removed, not yet fully
# compacted); the three gate docs (evaluation / production / record) are
# un-migrated. The four reference docs hold split-out top-level sections and are
# part of the closed workflow doc set, but they do not run loop/gate-only checks.
