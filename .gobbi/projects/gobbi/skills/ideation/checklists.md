# Ideation Checklist

Mode: evaluation coverage register. Run style: `do-confirm`. This reusable source is intentionally unchecked. Each `IDEA-CK-01` through `IDEA-CK-16` heading is a scenario-family group; the lettered entries beneath it are the atomic checklist items. Work a fresh filled copy, identify this source version and the evaluation run, inspect the named evidence, and resolve every applicable item only as `PASS`, `FAIL:<finding-id>`, or `n/a:<property>`.

## IDEA-CK-01 — Root Outcome and Scope

- [ ] **IDEA-CK-01A [REQUIRED, do-confirm] Problem-design alignment.** Applicability: unconditional. Claim: the selected design addresses the defined problem and desired outcome. Pass: direct comparison proves the selected design addresses the defined problem and produces the established desired outcome. Evidence: final problem definition and selected design. On fail: open a Project finding. Sources: Phase 1; Phase 3; IDEA-SC-01.
- [ ] **IDEA-CK-01B [REQUIRED, do-confirm] Observable outcomes.** Applicability: unconditional. Claim: the established result and requirements are observable. Pass: the final result and every material requirement state an observable outcome that proves the defined goal is achieved. Evidence: result, requirement blocks, and final trace. On fail: open a Project finding. Sources: Phase 1; IDEA-SC-01.
- [ ] **IDEA-CK-01C [REQUIRED, do-confirm] Scope enumeration.** Applicability: unconditional. Claim: the final scope is complete. Pass: direct comparison proves every material outcome is explicitly in scope, out of scope, deferred, or rejected and no undeclared outcome remains. Evidence: scope sections and change disclosure. On fail: open a Project finding. Sources: Phase 1; IDEA-SC-01.
- [ ] **IDEA-CK-01D [GATE, do-confirm] Material user decisions.** Applicability: unconditional. Claim: the user made every material outcome, scope, and design decision. Pass: direct decision evidence names the final desired outcome, complete scope, and selected design. Evidence: discussion and decision records. Consequence: a miss authorizes the wrong outcome or undeclared scope. On fail: reject completion and open a blocking Project finding. Sources: Rules “MUST preserve material user authority” and “NEVER change the accepted contract silently”; IDEA-SC-01.
