# Go Source Evaluation Checklist

## Project

### GOSRC-SC-PROJECT-01 — Normal case: Project import policy

The project has an accepted formatter or import tool. Source imports should match its grouping and ordering;
a difference from either form breaks the project contract.

#### Checklist

- [ ] GOSRC-CK-PROJECT-01-01 — Import grouping matches the project's import tool or formatter.
- [ ] GOSRC-CK-PROJECT-01-02 — Import ordering matches the project's import tool.

## Structure

### GOSRC-SC-STRUCTURE-01 — Poor quality: Unfocused source file

A source file can compile while mixing unrelated responsibilities. Its declarations should share a reason to
change; unrelated change drivers make the file structurally poor.

#### Checklist

- [ ] GOSRC-CK-STRUCTURE-01-01 — Each source file groups declarations that change for the same reason.

## Performance

Not applicable: source form does not establish runtime, build-time, or resource-efficiency behavior.

## Aesthetics

### GOSRC-SC-AESTHETICS-01 — Normal case: Canonical source layout

Valid Go source should use the project's canonical format. Hand alignment or a private line-length scheme
creates a competing visual form.

#### Checklist

- [ ] GOSRC-CK-AESTHETICS-01-01 — Every in-scope valid Go source file matches canonical project formatting, including removal of hand alignment that the formatter does not preserve.
- [ ] GOSRC-CK-AESTHETICS-01-02 — The source uses no private line-length scheme.

## Usage

### GOSRC-SC-USAGE-01 — Poor quality: Unexplained import form

Blank and dot imports can leave readers unable to identify an effect or symbol source. Their reason and dot-
import provenance should remain visible; hidden intent makes otherwise working source hard to use.

#### Checklist

- [ ] GOSRC-CK-USAGE-01-01 — Every blank or dot import has a visible reason.
- [ ] GOSRC-CK-USAGE-01-02 — Every dot import preserves visible symbol provenance.

## Consistency

### GOSRC-SC-CONSISTENCY-01 — Rule violation: Undeclared generated provenance

Generated source must identify its status, determining inputs, and generator. A missing declaration or a
change that does not correspond to the declared generator breaks the provenance contract.

#### Checklist

- [ ] GOSRC-CK-CONSISTENCY-01-01 — Every generated Go file carries its required generated source marker.
- [ ] GOSRC-CK-CONSISTENCY-01-02 — Every input that determines a generated change has declared ownership.
- [ ] GOSRC-CK-CONSISTENCY-01-03 — Every generated change corresponds to its declared generator.

### GOSRC-SC-CONSISTENCY-02 — Normal case: Stable regeneration

Accepted generated-source corrections should survive the owned generation path. Losing a correction during
regeneration makes the source and generator inconsistent.

#### Checklist

- [ ] GOSRC-CK-CONSISTENCY-02-01 — Regeneration preserves every accepted generated-source correction.

## Risk

### GOSRC-SC-RISK-01 — Adversarial: Cosmetic justification for unusual imports

Source can make blank or dot imports look intentional without a narrow need. Each form should satisfy its
specific contract and remain confined to the context that justifies it.

#### Checklist

- [ ] GOSRC-CK-RISK-01-01 — Every blank import expresses a deliberate package-level side-effect contract.
- [ ] GOSRC-CK-RISK-01-02 — Every dot import has a material narrow-test clarity benefit.
- [ ] GOSRC-CK-RISK-01-03 — Blank imports remain limited to focused integration points, and dot imports remain limited to narrow tests.
- Also applies: GOSRC-CK-USAGE-01-01 (visible import reason).
- Also applies: GOSRC-CK-USAGE-01-02 (visible dot-import provenance).

### GOSRC-SC-RISK-02 — Expected failure: Invalid source blocks formatting

Invalid Go source cannot establish canonical formatter output. The source should not be presented as canonical,
and the formatter blocker should remain visible instead of being hidden.

#### Checklist

- [ ] GOSRC-CK-RISK-02-01 — Invalid Go source is not represented as canonical.
- [ ] GOSRC-CK-RISK-02-02 — A formatter blocker caused by invalid source remains visible.

## Overall

### GOSRC-SC-OVERALL-01 — Adversarial: Generated output masks owned-source work

Generated output can appear complete while the required change is missing from owned source. The result fails
when generated bytes substitute for that owned change.

#### Checklist

- [ ] GOSRC-CK-OVERALL-01-01 — Generated output does not substitute for a required owned-source change.
- Also applies: GOSRC-CK-CONSISTENCY-01-01 (generated marker).
- Also applies: GOSRC-CK-CONSISTENCY-01-02 (declared generator inputs).
- Also applies: GOSRC-CK-CONSISTENCY-01-03 (declared generator correspondence).
- Also applies: GOSRC-CK-CONSISTENCY-02-01 (stable regeneration).
