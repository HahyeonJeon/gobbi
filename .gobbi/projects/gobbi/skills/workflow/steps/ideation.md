# Ideation Manager Adapter

[`ideation/SKILL.md`](../../ideation/SKILL.md) owns the What, Why, and How method. This adapter owns only manager entry, dispatch inputs, user gates, completion proof, and transitions.

## Entry

Enter Ideation DISCUSSION from Configuration or a user-authorized return. Supply the leader with the user's framing, project memory, applicable rules and mistakes, relevant code and history, prior valid artifacts, and any accepted evaluation dispositions. On a new iteration, identify changed inputs rather than treating the prior synthesis as authority.

## DISCUSSION

Dispatch the leader under [`delegation.md`](../delegation.md). The leader researches and frames the problem according to the specialist method. The manager discusses its evidence with the user and obtains explicit decisions for scope, success criteria, design direction, material assumptions, external research adoption, and deferred work.

DISCUSSION completes when the user has locked a neutral contract sufficient for two independent drafts and all material unknowns have an owner or explicit decision. Checkpoint project, feature, or task identity when it first becomes known, then transition to WORK.

## WORK

Run [`dual-system-work.md`](dual-system-work.md) with the leader role, locked Ideation contract, accepted research, user decisions, and applicable memory as identical inputs. The synthesis must express a coherent, plan-ready What, Why, and How without deciding Planning's Who, When, or Where.

## EVALUATION

Run [`evaluation.md`](evaluation.md). Give both fresh evaluators the complete creation package, resolved decisions, locked scope, applicable scenarios and checks, and the canonical synthesis. Do not omit any required perspective. Obtain the user's finding-disposition decision before transitioning to RECORD.

## RECORD and exit

Run [`record.md`](record.md). On PASS, verify the canonical Ideation artifact, typed staging actually supported by evidence, and the record command; then transition to Planning DISCUSSION. On REVISE or FAIL, use [`state-machine.md`](state-machine.md). A clean PASS may leave staging empty.
