# Phase 3 — Wrap-up and terminal Hand-off

Phase 3 promotes supported durable material, builds the evaluated handoff, performs configured Git
finalization, and reports the exact recovery state. It runs continuously without routine user questions or
deliberate idle.

[`SKILL.md`](SKILL.md) owns routing, the universal cycle, the fast gate, and terminal conditions. This document
supplies Wrap-up inputs, promotion, closeout evidence, and recovery details.

## Entry and continuous operation

Enter with `P3 · Wrap-up · DISCUSSION · 1/2` in progress and a verified Phase 2 Hand-off.

After each returned artifact, verify it, retitle or complete the current TODO, activate the next stage, and
continue immediately. Ask the user only when the critical-blocker boundary requires missing safety or
authority, a required system lacks waiver authority, or closure would require an extremely material change
outside the Phase 1 contract.

An optional remote action without authority is not automatically a blocker. Complete the authorized local
outcome, retain the branch and worktree, and report the unperformed action factually unless the locked outcome
made that action mandatory.

## Wrap-up cycle

### DISCUSSION

Give the Wrap-up specialist:

- canonical Ideation and Planning artifacts;
- every completed Execution task and focused commit;
- verification and evaluation evidence;
- accepted findings and material decisions;
- system waivers;
- typed staging inventory;
- durable destination preimages;
- memory and record rules;
- handoff requirements; and
- configured Git finalization authority.

Agents resolve:

- which typed candidates have sufficient evidence;
- source-to-destination promotion mapping;
- empty staging;
- handoff content;
- unresolved items and recovery;
- local commit coverage;
- configured publication steps; and
- actual authority for merge or cleanup.

Do not invent a durable item to populate empty staging and do not promote material that lacks typed evidence.

### WORK

1. Give Claude and Codex the same frozen closure contract.
2. Require independent promotion-and-handoff drafts.
3. Freeze both drafts before reciprocal review.
4. Run reciprocal reviews as later, separate operations and freeze both.
5. Let the active runtime's specialist synthesize:
   - the complete promotion manifest;
   - the shared handoff body;
   - the verification plan; and
   - the finalization-receipt shape.
6. Let one authorized writer apply only the resolved promotion inside the isolated worktree.
7. Verify every changed durable path against one staged source.
8. Verify source evidence remains unchanged and the applied result is repeatable.
9. Validate the dual-system package with the exact command in
   [`phase-1.md`](phase-1.md) § Shared evidence adapter.
10. Freeze the actual post-promotion tree and handoff for EVALUATION.

The session handoff and any durable handoff note use the same substantive body. A factual finalization receipt
may be added only after evaluation and must not rewrite the evaluated claims.

### EVALUATION

Dispatch one fresh Claude evaluator and one fresh Codex evaluator. Neither may be a creator, persistent
teammate, or recipient of the other evaluator's report.

Both inspect:

- the complete creation package;
- the actual post-promotion worktree;
- source and destination evidence;
- the promotion manifest;
- the handoff;
- local commits and checks;
- the configured Git plan; and
- retained recovery paths.

Both cover Project, Structure, Performance, Aesthetics, Usage, Consistency, Risk, and Overall and use the
shared evidence adapter's report format.

Preserve both declared report verdicts, then write a fast `gate.md`:

- PASS when no unresolved Critical or `blocking: yes` finding remains, even if a report declares REVISE for
  another finding;
- REVISE on iteration 1 when either blocking class remains; or
- FAIL and stop on iteration 2 when either blocking class remains.

Record optional improvements and nonblocking problems as accepted nonblocking findings. Do not force a third
iteration.

### RECORD

For every verdict:

1. seal the current creation and evaluation evidence;
2. preserve both evaluator provenances;
3. write `gate.md` with report paths, hashes, declared verdicts, blocking IDs, accepted nonblocking IDs, and
   workflow decision;
4. verify promotion source and destination mappings;
5. verify the shared handoff body;
6. stage no unsupported material;
7. preserve branch and worktree recovery;
8. write `record/iteration-N.md` with the exact TODO, package and report hashes, gate hash, promotion checks,
   canonical output, and staging; and
9. update the TODO only after rereading that receipt and its evidence.

On PASS, write and verify canonical Wrap-up evidence before Git finalization.

## Git finalization

Perform only configured and authorized actions:

1. confirm every in-scope change has a verified focused local commit;
2. create any required final local documentation or promotion commit;
3. verify the committed tree and expected worktree state;
4. perform configured publication when already authorized;
5. merge only with explicit authority and satisfied preconditions;
6. clean up only after a confirmed merge and verified safe preimage; and
7. otherwise retain the branch and worktree.

Record actual outcomes for:

- local commits;
- publication;
- pull request;
- merge;
- cleanup;
- branch; and
- worktree.

A failed or deferred external action must retain an exact next action. Never report an intended action as
completed.

## Terminal Hand-off

Render:

```text
Phase: Phase 3
Outcome: <completed authorized session outcome>
Completed: <Wrap-up, promotion, verification, and authorized Git actions>
Evidence: <canonical artifacts, commits, checks, and evaluations>
Decisions: <material and autonomous closeout decisions>
Accepted nonblocking findings: <findings or none>
Branch: <actual retained or finalized branch>
Worktree: <actual retained or removed worktree>
Next TODO: none — workflow complete
Continuation: terminal
```

Append the factual finalization receipt. Complete `P3 · Hand-off` only when that receipt agrees with Git and
filesystem evidence.

Display the Hand-off and end the workflow. If the branch or worktree remains, the checkpoint must give the
exact first recovery action.
