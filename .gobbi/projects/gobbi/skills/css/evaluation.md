# CSS evaluation extension

Use the general Evaluation method and report schema. This file only selects
CSS-specific evidence; it adds no caller schema or parent policy.

## Perspectives

- **Project:** exact authorized CSS outcome, targets, scope, independent use,
  and owner boundaries.
- **Structure:** fixed operation shape, parent-owned rules, one-hop references,
  scenario obligations, atomic checklist gates, and trace closure.
- **Performance:** measured problem, representative before/after result,
  behavior/accessibility guard, and removal criterion.
- **Aesthetics:** readable cascade architecture, conventional naming, coherent
  visual-state system, and absence of override/feature-fashion clutter.
- **Usage:** executable procedure, routable children, usable checklist pause
  points, failure recovery, and browser/Electron renderer applicability.
- **Consistency:** CSS-1–CSS-4 agree with children, scenarios, checklist,
  evidence, targets, and completion language.
- **Risk:** accessibility-controlled rendering, trust/generator/runtime seams,
  proprietary/experimental features, four-link identity, and claim ceiling.
- **Overall:** integrate the seven perspectives using the general severity
  rule; do not average away a gate failure.

## Recommended verification

Safe/static: exact inventory/frontmatter/links, rule and field audit, selector/
syntax checks, source/transform identities, and scoped Git diff.

Exact-byte-bound: CSSOM/rule presence, matched/cascade/computed values, layout/
overflow/scroll geometry, target/mode rendered comparisons, performance
measurements, fallback/failure/recovery, and digest equality.

Excluded proof remains explicit: these methods do not prove runtime skill use,
product accessibility conformance, UI/UX acceptance, or deployment.

## Anti-patterns

- support label or `@supports` presented as correctness;
- screenshot presented as cascade, accessibility, or responsive proof;
- lint/link/ID occurrence presented as semantic closure;
- performance hint without representative measurement and guard;
- emitted-byte repair or observation bound to different bytes;
- hidden HTML/UI/UX/web prerequisite or CSS-owned Electron process policy;
- checklist source prechecked or bare FAIL/N/A resolution.

## Overall anchors

- **PASS:** both gates close; field-level trace and exact-byte evidence support
  every applicable CSS rule; no material limitation is hidden.
- **REVISE:** an owned repair can close a missing/failed field without changing
  the accepted outcome or scope.
- **FAIL:** the CSS outcome is unsafe, nonconforming, unobservable, outside
  authority, or requires a material design/scope decision.

Every finding cites rule, obligation/check, exact bytes/target, observation,
consequence, owner, and root-cause repair. After repair, regenerate/rebind when
applicable and repeat the complete affected selection.
