# Wrap-up Evaluation Entry

Use this entrypoint with [evaluation/SKILL.md](../evaluation/SKILL.md). It supplies closure-specific lenses for the one complete report. Memory-type companions may add cases and checks but cannot replace this frame or the central schema.

## Required inputs

- locked closure contract, scope, canonical step and task artifacts, approved dispositions, waivers, commits, verification, and authorized Git plan;
- both Wrap-up drafts and reciprocal reviews plus resolved decisions;
- complete typed-staging inventory, candidates, frozen manifest and digest, whole-file preimages, and source identities;
- actual post-promotion project tree, applied-delta comparison, prior-staging hashes, and all applicable guard results;
- matching session and durable handoff candidates with required note frontmatter;
- [scenarios.md](scenarios.md) and [checklists.md](checklists.md); and
- dual-work package validation and exact subject digest.

## Perspective lenses

### Project

Compare agreed scope, canonical artifacts, task results, staging accounting, durable delta, and handoff claims. Detect omitted results, unrelated memory, wrong-session evidence, phantom completion, and a deferred item stated as shipped.

### Structure

Inspect typed source routing, destination ownership, frontmatter, areas, manifest completeness, whole-file preimages, shared destinations, reciprocal lifecycle links, archive paths, inbound-reference carriers, and session/durable handoff placement. Every actual changed path must map to one mutation row.

### Performance

Inspect inventory, hashing, rendering, shared-file assembly, validation, apply order, retry, and guard cost. Require direct evidence where batch size, large records, or shared destinations make resource claims material. Detect repeated whole-tree scans or one rewrite per source.

### Aesthetics

Inspect the nine-section handoff for plain language, stable headings, useful link text, concise facts, accurate names, and absence of filler or unsupported celebration. Inspect manifest and evidence artifacts for scan-friendly stable order.

### Usage

Cold-read the handoff as the next manager. Verify objective, required reads, branch and worktree facts, first action, decisions, risks, exceptions, unresolved reasons, and recovery instructions. Check accessible hierarchy, unambiguous dates, and locale-independent commands and paths.

### Consistency

Compare inventory, candidates, manifest, preimages, actual delta, prior-staging hashes, lifecycle records, references, guard output, report subject digest, both handoff bodies, dispositions, commits, and Git plan. Search for a changed path without a row, row without a result, stale reference, or claim without evidence.

### Risk

Inspect root containment, symlinks, wrong-worktree and main-checkout risk, protected data, path input, drift, partial apply, idempotency, destructive lifecycle work, rollback, publication authority, merge authority, and cleanup boundaries. The evaluated subject is the actual post-promotion tree.

### Overall

Challenge a perfect intended manifest whose applied bytes differ, a matching handoff pair that shares one false claim, hidden non-staging input, partial evidence disguised as empty staging, and checks weakened to accept the result. Preserve exact source accounting, recoverability, and evidence-linked next actions.

## Recommended verification

Use safe read-only commands against the session and project tree: sorted staging inventory and hashes, manifest-to-diff comparison, whole-file preimage comparison, root and symlink resolution, frontmatter and memory validators, link and vocabulary checks, prior-staging rehash, body comparison, Git branch/worktree/status inspection, and exact record verification. Record any mutating command as part of the already frozen apply evidence; do not rerun it during review.
