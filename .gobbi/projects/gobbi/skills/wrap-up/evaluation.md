# Wrap-up Evaluation Entry

Use this entrypoint with [evaluation/SKILL.md](../evaluation/SKILL.md). It supplies closure-specific lenses for
one complete evaluation result. Memory-type companions may add cases and checks but cannot replace the general
method. A calling workflow owns its schema and output mechanics.

## Required inputs

- locked closure contract, scope, canonical step and task artifacts, approved dispositions, waivers, commits, verification, and authorized Git plan;
- both Wrap-up drafts and reciprocal reviews plus resolved decisions;
- complete typed-staging inventory, candidates, frozen manifest and digest, whole-file preimages, and source identities;
- actual post-promotion project tree, applied-delta comparison, prior-staging hashes, and all applicable guard results;
- matching session and durable handoff candidates with required note frontmatter;
- [scenarios.md](scenarios.md) and [checklists.md](checklists.md); and
- dual-work package validation and exact subject digest.

## Perspective lenses

### Project

Compare agreed scope, canonical artifacts, task results, staging accounting, durable delta, and handoff claims. Detect omitted results, unrelated memory, wrong-session evidence, phantom completion, and a deferred item stated as shipped.

### Structure

Inspect typed source routing, destination ownership, frontmatter, areas, manifest completeness, whole-file
preimages, shared destinations, true-successor reciprocity, non-successor terminal semantics,
status/reason compatibility, sole project-root archive paths, frozen archive bodies, active
inbound-reference carriers, live namespace changes, and session/durable handoff placement. Every actual
changed path must map to one mutation row.

### Performance

Inspect inventory, hashing, rendering, shared-file assembly, validation, apply order, retry, and guard cost. Require direct evidence where batch size, large records, or shared destinations make resource claims material. Detect repeated whole-tree scans or one rewrite per source.

### Aesthetics

Inspect the nine-section handoff for plain language, stable headings, useful link text, concise facts, accurate names, and absence of filler or unsupported celebration. Inspect manifest and evidence artifacts for scan-friendly stable order.

### Usage

Cold-read the handoff as the next manager. Verify objective, required reads, branch and worktree facts, first action, decisions, risks, exceptions, unresolved reasons, and recovery instructions. Check accessible hierarchy, unambiguous dates, and locale-independent commands and paths.

### Consistency

Compare inventory, candidates, manifest, preimages, actual delta, prior-staging hashes, lifecycle records,
default live and explicit strict archive guard output, archived-body preimage comparisons, scoped active
link inputs and output, report subject digest, both handoff bodies, dispositions, commits, and Git plan.
Search for a changed path without a row, row without a result, illegal archive pair or location,
rewritten archive-body link text, invented successor, stale active reference, an archive exclusion
borrowed by a live namespace move, or a claim without evidence.

### Risk

Inspect root containment, symlinks, wrong-worktree and main-checkout risk, protected data, path input, drift, partial apply, idempotency, destructive lifecycle work, rollback, publication authority, merge authority, and cleanup boundaries. The evaluated subject is the actual post-promotion tree.

### Overall

Challenge a perfect intended manifest whose applied bytes differ, a matching handoff pair that shares one
false claim, hidden non-staging input, partial evidence disguised as empty staging, and checks weakened to
accept the result. Separately probe an expected unresolved outbound link inside a frozen archive body, a
stale active inbound carrier, and a broken live namespace link. Preserve exact source accounting,
recoverability, and evidence-linked next actions.

## Recommended verification

Use safe read-only commands against the session and project tree: sorted staging inventory and hashes,
manifest-to-diff comparison, whole-file preimage comparison, root and symlink resolution, no-argument
live frontmatter validation, explicit validation of each new project-root archive, link and vocabulary
checks over every changed active Markdown file, prior-staging rehash, archive-preimage and handoff-body
comparisons, Git branch/worktree/status inspection, and exact record verification. Confirm archive bodies
are absent from relative-link inputs without omitting strict validation, body identity, lifecycle, or
actual-tree proof. Confirm active carriers and live namespace moves remain in scope. Record any mutating
command as part of already frozen apply evidence; do not rerun it during review.
