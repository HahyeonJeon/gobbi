# Material revisions require full dual-system WORK

## Insight

A material revision is a new subject, even when it starts from a precise approved finding list. It requires a complete new dual-system WORK package and two fresh complete EVALUATION reports. The expected effort or apparent narrowness of the fix does not reduce the independence requirement.

## Context

In the historical workflow, the manager treated targeted remediation as lower-yield for independent creation and used one system to revise before returning to dual review. That preserved evaluator diversity but removed creation-time diversity from the exact iteration most likely to inherit the original author's assumptions.

## Reason

An approved fix list describes findings and dispositions; it does not prove one correction strategy is complete. Independent drafts can expose different root-cause fixes, preservation risks, or secondary effects. Reciprocal review then tests those alternatives before synthesis. Skipping that path creates a shared-blind-spot risk that later evaluation cannot fully reconstruct.

## How

After the user approves the finding-disposition batch, start `iteration-{n+1}`. Give Claude and Codex the same complete revised contract and prior accepted evidence. Freeze both independent drafts, run both reciprocal cross-reviews, synthesize a new canonical candidate, and resolve all material open decisions. Then dispatch two fresh independent evaluators for all seven perspectives plus Overall, the complete ledger, and checklist.

Keep the prior iteration wholly immutable. Do not reuse a creator or evaluator artifact as the new system contribution. Never remove one system, a perspective, creation evidence, or repeat review because the change appears mechanical or token cost is high. A missing system pauses the workflow unless the user grants an exact waiver for that named system, step, and iteration.

## Counter-cases

- A byte-only renderer repair that provably does not change the canonical artifact's material meaning may remain a storage correction, but the owner validator must prove that boundary.
- A missing-system waiver changes the PASS rule only for its exact named operation. It does not create a reusable single-system revision class.
- If a proposed correction cannot be classified confidently as non-material, treat it as material and run the full iteration.
