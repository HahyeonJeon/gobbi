# CLI may regenerate `.gobbi/.gitignore` with the pre-reset policy at next bootstrap

## Context

In the 2026-05-21 bottom-up repo reset (this session), `.gobbi/.gitignore` is edited to remove the lines `sessions/` and `project/note/` — per user lock Q-E, "the sessions and project/note/ should not be gitignored from now." `worktrees/` and `settings.json` remain ignored.

The risk: `.gobbi/.gitignore` is auto-generated by the gobbi CLI at workspace bootstrap. The regenerator source historically lived under `packages/cli/` — which is being deleted entirely in the same sweep (Q1). The next time a CLI runs against this workspace (after the rebuild lands a new CLI), it may re-write this file with the old policy (re-ignoring `sessions/` and `project/note/`), silently undoing the user's lock.

## Why deferred

The rebuild is the explicit follow-on session and is out of scope for this cleanup PR. The CLI source that would need adjusting does not exist in the working tree post-sweep (`packages/` is wiped), so there is no place to fix the regenerator in this session. The fix has to land as part of (or alongside) the new CLI build.

## When to pick up

When the rebuild session adds the `.gobbi/.gitignore` template / regeneration logic to the new CLI. Before that logic ships, audit it against the locked policy:

- IGNORE: `worktrees/`, `settings.json`
- DO NOT IGNORE: `sessions/`, `project/note/`

If the new CLI emits the old policy by default, either change the template or add an opt-out flag honoring the user's lock for the gobbi project.

## Suggested approach

1. Locate the regenerator template in the rebuilt CLI (likely a `gitignoreTemplate` or equivalent string constant in the workspace-init module).
2. Update the template to drop `sessions/` and `project/note/`.
3. Add a regression test that bootstraps a workspace and asserts the produced `.gobbi/.gitignore` contains neither `sessions/` nor `project/note/`.
4. Verify with `git check-ignore` after running the new CLI's init: the path `.gobbi/projects/gobbi/sessions/<session-id>/session.json` must NOT be ignored.
