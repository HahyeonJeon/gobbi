### F1 — flock semantics (R1 / COD-STRUCT-002)

D-3-5 adds `flock -x` on `session.json` for both hook and reconstructor. Verify:
- Does the design specify EXCLUSIVE lock for both read-modify-write cycles (hook AND reconstructor)?
- Is the lock acquired BEFORE the read (not just before the write)?
- Does the flock release on process exit (per POSIX flock(2) semantics — the draft claims this)?
- Does the design address the race scenario where: hook A reads → hook B reads → A writes → B writes → B clobbers A? The E-5 scenario describes this; does D-3-5 actually close it given `flock -x` semantics?

Empirical check: does `flock -x "$fd"` on a descriptor opened with `exec {fd}>>"$session_json"` provide the mutual-exclusion guarantee the design claims? (Advisory: POSIX `flock(2)` on Linux: `flock -x` acquires exclusive lock; yes it blocks concurrent `flock -x` on the same file by different processes.)
