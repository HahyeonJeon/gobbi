# UI Design Lifecycle Overlay

Select this overlay only when accepted evidence identifies an interactive visual interface. It adds
interface-specific visual-production questions without owning Product behavior or Development mechanisms.

## Project

- [ui-cross-product-coherence] Which interface patterns and visual states must remain coherent across Project Products?

## Product

- [ui-state-inventory] Which ordinary, empty, loading, partial, error, success, disabled, and permission states need distinct visual treatment?

- [ui-action-hierarchy] Which actions must appear primary, secondary, destructive, unavailable, or reversible in each relevant state?

- [ui-navigation-orientation] Which visual cues keep a person oriented within the interface and its current task?

- [ui-feedback-timing] What visual feedback must appear during immediate, delayed, partial, and completed interaction?

- [ui-responsive-composition] How should hierarchy, density, controls, and content reflow across accepted viewport and container sizes?

- [ui-input-visuals] Which focus, hover, pressed, selected, invalid, autofilled, and read-only states must remain distinguishable?

- [ui-design-system-fit] Which accepted interface-system components, tokens, and patterns should the visual design reuse or extend?

- [ui-motion-continuity] Which interface transitions need motion to preserve spatial or state continuity, and what reduced-motion treatment preserves meaning?

- [ui-assistive-visual-equivalence] Which visual relationship or state needs an equivalent name, order, cue, or text alternative?

## Implementation

- [ui-state-handoff] Which UI states, responsive variants, component relationships, and interaction transitions must visual handoff cover?

- [ui-visual-regression-set] Which representative interface states and viewport conditions form the visual quality comparison set?
