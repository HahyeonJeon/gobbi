# Report Design Lifecycle Overlay

Select this overlay only when accepted evidence identifies a structured visual report. It covers visual
reading, comparison, reference, and publication without owning the source data's Product contract.

## Project

- [report-family-coherence] Which recurring or related reports must share a visual identity and navigation model?

## Product

- [report-reading-purpose] Which decisions, review tasks, or reference needs should the report's visual structure support?

- [report-information-architecture] Which summary, finding, evidence, detail, and appendix layers should organize the report?

- [report-scan-path] What must a time-limited reader find first, and how can they reach supporting detail?

- [report-evidence-display] Which chart, table, diagram, annotation, or prose form best represents each material claim and its uncertainty?

- [report-source-visibility] How should sources, definitions, dates, caveats, and data limits remain visible without obscuring the main reading path?

- [report-table-legibility] Which dense table, long label, footnote, pagination, or repeated header condition sets the layout stress case?

- [report-print-digital] Which hierarchy, color, links, navigation, and page behavior must survive print and digital forms?

- [report-accessibility] Which reading order, heading structure, tagged content, text alternatives, contrast, and table semantics are required?

- [report-update-variation] Which visual elements stay fixed or adapt when a recurring report's content, length, or evidence changes?

## Implementation

- [report-publication-package] Which source visuals, linked assets, fonts, accessible output, print proof, and publication variants must handoff include?

- [report-output-inspection] What inspection proves that pagination, figures, tables, links, type, color, and accessibility survive final output?
