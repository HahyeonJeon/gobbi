# Preference Skill Checklist

> **Document role:** Reusable unchecked evaluation source<br>
> **Subject:** Preference skills authored or substantively revised through Preference Skill<br>
> **Applicability:** One complete current preference skill and its accepted consistency design; Evaluation binds the exact files, bytes, consumers, recurring choices, and authority under review<br>
> **Purpose:** Evaluate whether a preference skill produces consistent agent results without suppressing valid variation or becoming an SOP<br>
> **Scope:** Consistency need, authority, guidance classes, categories, recurring choices, expected forms, defaults, exceptions, examples, and result convergence<br>
> **Exclusions:** Shared Gobbi Skill requirements; configured-tool behavior owned elsewhere; one-time decisions; execution results; operating product behavior<br>
> **Governing sources:** [Checklist](../../checklist/SKILL.md), [Gobbi Skill](../SKILL.md), [Preference Skill](SKILL.md), the accepted consistency design, and applicable project authorities<br>
> **Context:** Apply the [Gobbi Skill checklist](../checklist.md) in parallel. Evaluate Preferences as the core and add subject-specific items after study.<br>
> **Checkbox meaning:** Check an item when evidence shows the problem is present.

## Project Lifecycle

### Consistency Boundary

#### The preference system governs an unclear, unsupported, or nonrecurring choice

- [ ] The intended consumer cannot be identified.
- [ ] The recurring decision cannot be identified when the subject is a choice.
- [ ] The recurring artifact cannot be identified when the subject is an output.
- [ ] The consistency result cannot be identified.
- [ ] The context that needs consistency cannot be identified.
- [ ] The target standardizes a one-time choice.
- [ ] The target standardizes a difference that causes no material consistency problem.
- [ ] A recurring material choice remains uncovered.
- [ ] A configured tool already controls the choice completely.
- [ ] An accepted decision already controls the choice completely.
- [ ] A stronger project authority already controls the choice completely.
- [ ] The target is primarily an ordered procedure.
- [ ] The target is primarily a named-tool manual.
- [ ] The target is primarily a domain navigation root.

### Authority

#### Conflicting guidance has no clear and valid controlling source

- [ ] A retained claim cannot be traced to a governing source.
- [ ] Conflicting authorities lack a clear precedence.
- [ ] An authority conflict lacks a stop condition when precedence cannot resolve it.
- [ ] A generic default overrides an applicable project authority.
- [ ] A borrowed fact is indistinguishable from locally owned policy.
- [ ] The same preference has more than one policy owner.
- [ ] The same constraint has more than one policy owner.

## Design and Development Lifecycle

### Guidance Classes

#### Rules, Preferences, facts, and exceptions are assigned to the wrong roles

- [ ] A non-negotiable requirement appears only as a Preference.
- [ ] A required convention appears only as a Preference.
- [ ] A recommendation that admits valid variation appears as a Rule.
- [ ] A borrowed fact is stated as locally owned policy.
- [ ] An exception changes a Rule.
- [ ] An exception bypasses a Rule.
- [ ] A Principle repeats a consistency choice instead of explaining the durable model.
- [ ] A Principle repeats a constraint instead of explaining the durable model.
- [ ] Conflicting same-level Preferences lack a deterministic decision criterion.

### Preference Structure

#### The category-to-choice-to-detail structure does not match the recurring decisions

- [ ] Preferences is absent.
- [ ] Preferences is not the dominant consistency section.
- [ ] A top-level Procedure is present.
- [ ] A top-level Manual is present.
- [ ] The top-level sections appear outside the required preference-skill order.
- [ ] A consistency area is not a `###` category directly below Preferences.
- [ ] A recurring choice is not a `####` subtitle below its category.
- [ ] A Preference detail is not rendered as a bullet below its subtitle.
- [ ] A category combines consistency areas with different contexts.
- [ ] A category combines consistency areas with different authorities.
- [ ] A subtitle combines choices that can produce different results.
- [ ] A subtitle combines choices with different exception boundaries.
- [ ] A subtitle has more than three details.
- [ ] A detail has more than two sentences.
- [ ] A detail does not put the expected or recommended result first.
- [ ] Supporting material sits outside the detail it supports.

### Defaults and Variation

#### Defaults are unclear or override valid variation

- [ ] A default is implied without identifying its expected result.
- [ ] A default applies where stronger authority has already resolved the choice.
- [ ] A default lacks the context in which stronger authority leaves the choice open.
- [ ] A default lacks a departure condition when a different result can be valid.
- [ ] A Preference lacks the context needed to decide when it applies.
- [ ] A permitted departure lacks a named condition.
- [ ] A permitted departure lacks supporting evidence.
- [ ] A valid difference required by context is prohibited.
- [ ] A valid difference required by evidence is prohibited.
- [ ] A valid difference required by accessibility is prohibited.
- [ ] A valid difference required by safety is prohibited.
- [ ] A valid difference required by user need is prohibited.
- [ ] An outside-scope case is silently forced through the preference.

#### Equivalent cases can produce inconsistent results

- [ ] Equivalent cases under the same authority and context can produce different results.
- [ ] The expected result is too vague to reproduce.
- [ ] An observable output property needed for repeatability is undefined.
- [ ] An ordinary case requires private author context to select the expected result.
- [ ] A permitted-variation case cannot be distinguished from an authority conflict.

### Clarity and Support

#### Supporting language or examples weaken consistent use

- [ ] A subjective word stands in for an observable decision criterion.
- [ ] A rationale does not help apply the result.
- [ ] A contrast does not help distinguish the result from a valid alternative.
- [ ] An example does not help apply the result.
- [ ] An example contradicts its owning Preference.
- [ ] An example silently narrows a permitted variation.
- [ ] Different terms describe the same consistency choice without a necessary distinction.
